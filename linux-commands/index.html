    Linux: команды с подробным описанием

    Справочник по командам Linux. Основная теория (компоненты системы, процессы и сессии) — на странице Linux (теория).

    Навигация и работа с файлами

    ls — просмотр содержимого каталога

    • ls - просмотр объектов в каталоге
    Флаг Описание Пример
    -l Подробный список (права, владелец, размер, дата) ls -l
    -a Показывает все файлы, даже скрытые ls -a
    -h Человеко-читаемый размер (KB, MB, GB) ls -lh
    -r Обратный порядок сортировки ls -lr
    -t Сортировка по времени изменения (новые первыми) ls -lt
    -S Сортировка по размеру (большие первыми) ls -lS

    cd / pwd

    • cd <path> - перейти в каталог (cd .. — на уровень выше, cd ~ — в домашний)
    • pwd - показать текущий каталог (print working directory)

    cat — просмотр содержимого файла

    • cat <file> - вывести содержимое файла на экран
    • cat file1 file2 - склеить несколько файлов
    • cat > file << EOF ... EOF - создать файл из ввода

    ⚠️ cat выводит весь файл. Для больших файлов лучше less/head/tail.

    less / head / tail — чтение больших файлов

    Команда Что делает
    less <file> Постраничный просмотр (пробел/стрелки — листать, q — выйти)
    head -n N <file> Первые N строк
    tail -n N <file> Последние N строк
    tail -f <file> Следить за файлом в реальном времени (удобно для логов) 
    $ tail -f /var/log/nginx/access.log

    touch — создание пустого файла

    • touch <file> - создать пустой файл (или обновить время изменения у существующего)
    • touch -t 202601011200 file - задать время изменения вручную

    mkdir — создание каталога

    • mkdir <dir> - создать каталог
    • mkdir -p a/b/c - создать всю цепочку вложенных каталогов разом

    rm — удаление

    • rm <file> - удалить файл (для директории выдаст ошибку)
    • rm -r <dir> - удалить директорию со всем содержимым (recursive)
    • rm -f <file> - принудительное удаление без запроса (force)
    • rm -rf <dir> - принудительно удалить каталог со всем внутри

    ⚠️ rm -rf необратимо. Дважды проверь путь, прежде чем нажимать Enter.

    cp / mv / ln

    • cp <src> <dst> - копировать файл/каталог (для каталога -r)
    • mv <src> <dst> - переместить или переименовать
    • ln -s <target> <link> - создать символическую ссылку (как ярлык)
    $ cp config.conf config.bak
$ cp -r projects/ backup/
$ mv report.txt final.txt      # переименование
$ ln -s /usr/bin/python3 /usr/local/bin/python

    find — поиск файлов

    • find <путь> <условие> - поиск файлов/каталогов по имени, типу, времени
    Флаг Описание Пример
    -name По имени файла find /etc -name "*.conf"
    -type По типу (f=файл, d=каталог) find . -type d
    -mtime По времени изменения (в днях) find /var/log -mtime -7
    -size По размеру find . -size +100M
    -exec Выполнить команду для каждого результата find . -name "*.log" -exec rm {} \;

    Текстовые редакторы

    nano — простой редактор

    • nano <file> - открыть файл в редакторе

    Перед использованием удобно создать файл через touch.

    Горячие клавиши nano: Ctrl+O — сохранить, Ctrl+X — выйти, Ctrl+W — поиск, Ctrl+K — вырезать строку.

    vim — мощный редактор

    • vim <file> - открыть файл (может создать новый сразу)

    В отличие от nano, vim сразу создаёт файл, но имеет специфические режимы. Базовые команды нужно знать:

    Команда Действие
    i войти в режим вставки (вставить текст)
    Esc выйти из режима вставки
    :w сохранить (write)
    :q выйти (quit)
    :wq (или :x) сохранить и выйти
    :q! выйти без сохранения 
    $ vim nginx.conf
# нажимаем i, редактируем, Esc, :wq

    Текстовая обработка

    grep — поиск по содержимому

    • grep <pattern> <file> - поиск совпадений с регулярным выражением
    Флаг Описание Пример
    -i Игнорировать регистр grep -i error log.txt
    -r Рекурсивный поиск по каталогам grep -r "TODO" src/
    -n Показать номер строки grep -n "error" log.txt
    -v Инвертировать (показать НЕ совпадающие) grep -v "#" config.conf
    -c Подсчитать количество совпадений grep -c error log.txt
    -E Расширенные регулярные выражения (egrep) grep -E "err|fail" log.txt

    grep полезен при анализе логов: journalctl -u nginx | grep error, docker logs app | grep -i exception

    wc — подсчёт

    • wc -l <file> - число строк
    • wc -w <file> - число слов
    • wc -c <file> - число байт

    sort / uniq — сортировка и уникальность

    • sort <file> - отсортировать строки
    • sort -r - обратный порядок
    • uniq - убрать повторяющиеся подряд строки (обычно в связке с sort)
    • uniq -c - показать количество повторений
    $ sort access.log | uniq -c | sort -rn   # топ повторяющихся строк

    cut — вырезать колонки по разделителю

    • cut -d: -f1 /etc/passwd - вывести первое поле, где разделитель :
    • cut -c1-10 file - первые 10 символов каждой строки

    sed / awk — мощная обработка потока

    • sed 's/old/new/g' file - замена всех вхождений old на new
    • sed -i 's/old/new/g' file - замена с сохранением в файл (in-place)
    • awk '{print $1}' file - вывести первое поле каждой строки (по пробелам)
    • awk -F: '{print $1, $3}' file - задать разделитель : и вывести поля
    $ sed 's/8080/80/g' nginx.conf
$ awk '{print $NF}' /var/log/access.log   # последнее поле

    ⚠️ Без флага -i sed только печатает результат, не меняя файл. Хочешь применить — добавляй -i.

    Потоки, пайпы и редиректы

    Каждая команда имеет три стандартных потока: * stdin (0) - стандартный ввод * stdout (1) - стандартный вывод * stderr (2) - стандартный вывод ошибок

    Пайп | — передача вывода одной команды в другую

    $ ps aux | grep nginx          # процессы с "nginx" в выводе
$ docker logs app | grep error # ошибки в логах контейнера
$ ls -l | wc -l                # число файлов

    Редиректы > >> 2> <

    • cmd > file - записать вывод в файл (перезаписать)
    • cmd >> file - дописать в конец файла
    • cmd 2> err.log - ошибки — в файл
    • cmd 2>&1 - перенаправить stderr туда же, куда stdout
    • cmd < file - читать ввод из файла
    • /dev/null - «чёрная дыра» (вывод никуда)
    $ curl -s http://localhost:8000/health > health.json
$ echo "start" >> app.log
$ nginx -t 2>&1 | tee check.log   # и в файл, и на экран
$ some_cmd > /dev/null 2>&1       # полностью погасить вывод

    tee — пишет вывод и в файл, и в stdout одновременно.

    Комбинации && || ;

    • cmd1 && cmd2 - выполнить cmd2 только если cmd1 успешно (код 0)
    • cmd1 || cmd2 - выполнить cmd2, если cmd1 завершилось с ошибкой
    • cmd1 ; cmd2 - выполнить оба последовательно, не глядя на результат
    $ mkdir build && cd build && cmake ..   # по цепочке, остановится при ошибке
$ curl -f http://localhost/ || echo "сервис недоступен"
$ cd /tmp ; ls                          # выполнит оба

    Код возврата $?

    • $? - код возврата последней команды (0 = успех, ненулевой = ошибка)
    $ grep "error" app.log
$ echo $?    # 0 если нашёл, 1 если нет

    Управление процессами

    ps — список процессов

    • ps - процессы текущей сессии
    Флаг Описание Пример
    aux Все процессы (a=все, u=пользовательский формат, x=демоны) ps aux
    -ef Стандартный полный список ps -ef
    -u Процессы конкретного пользователя ps -u <user>
    -p Конкретный процесс по ID ps -p <PID>
    --forest Древовидный вид ps aux --forest

    top / htop — мониторинг в реальном времени

    • top - живой монитор процессов (обновляется каждые несколько секунд)
    • htop - улучшенная версия (цветной, с мышью), если установлен

    В top: q — выйти, k — убить процесс, M — сортировка по памяти, P — по CPU.

    kill / killall — завершение процессов

    • kill <PID> - отправить сигнал (по умолчанию SIGTERM — корректное завершение)
    • kill -9 <PID> - принудительно убить (SIGKILL — не даёт процессу завершиться)
    • kill -15 <PID> - то же, что kill (SIGTERM)
    • killall <name> - убить все процессы по имени
    $ kill 1234          # корректное завершение (может сохранить данные)
$ kill -9 1234       # принудительно (если не реагирует)
$ killall nginx      # завершить все процессы nginx

    Старайся сначала kill (SIGTERM) — процесс может успеть сохранить данные. kill -9 — только когда процесс «завис».

    jobs / bg / fg

    • Ctrl+Z - приостановить процесс
    • jobs - показать фоновые/приостановленные задачи
    • bg - продолжить задачу в фоне (background)
    • fg - вернуть задачу на передний план (foreground)
    • nohup cmd & - запустить команду, устойчивую к закрытию терминала
    $ sleep 100        # Ctrl+Z
$ jobs             # [1]+ Stopped  sleep 100
$ bg %1            # продолжить в фоне
$ fg %1            # вернуть на передний план

    lsof — открытые файлы и сокеты

    • lsof - открытые файлы и сокеты

    В Linux «всё есть файл» - обычные файлы, директории, сетевые сокеты, pipes.

    Флаг Описание Пример
    -i Сетевые соединения (TCP/UDP) lsof -i или lsof -i :3000
    -p Файлы, открытые процессом lsof -p <PID>

    Переменные окружения и вывод

    echo / printf — вывод

    • echo "text" - вывести строку
    • echo $VAR - вывести значение переменной
    • printf "формат %s\n" value - форматированный вывод (как в C)
    $ echo "Hello, $USER"
$ printf "Порт: %s\n" "8080"

    Переменные окружения

    • export NAME=value - создать/изменить переменную (станет доступна дочерним процессам)
    • printenv / env - показать все переменные
    • echo $NAME - прочитать значение
    • unset NAME - удалить переменную
    $ export REDIS_HOST=redis-cache
$ echo $REDIS_HOST
$ env | grep REDIS

    Часто встречается в Docker/CI: ${VAR:-default} — подставить значение или дефолт.

    alias — алиасы (сокращения)

    • alias ll='ls -la' - создать алиас
    • alias - показать все алиасы
    • unalias ll - удалить

    Системная информация

    $ uname -a          # версия ядра и системы
$ hostname          # имя хоста
$ date              # дата и время
$ uptime            # как долго работает, средняя нагрузка
$ free -h           # использование памяти
$ which curl        # где находится исполняемый файл curl
$ type cd           # тип команды (встроенная, алиас, внешняя)

    which/type полезны, чтобы понять, какая команда реально выполнится и откуда.

    Справка по командам

    • man <cmd> - подробная документация (q — выход)
    • <cmd> --help - краткая справка
    • help <builtin> - справка по встроенной команде

    history — история команд

    • history - показать историю команд
    • !! - повторить последнюю команду
    • !123 - повторить команду под номером 123
    • Ctrl+R - поиск по истории

    Условные проверки (test)

    • [ -f file ] - существует ли файл
    • [ -d dir ] - существует ли каталог
    • [ -x file ] - исполняемый ли файл
    • [ -z "$var" ] - переменная пустая
    • [ "$a" = "$b" ] - строки равны
    • Проверка в одну строку: [ -f app.log ] && echo "есть" || echo "нет"
    $ test -f /etc/nginx/nginx.conf && echo "конфиг есть"
$ [ -d /var/lib/mysql ] && echo "каталог БД существует"

    Права и владельцы

    chmod / chown

    • chmod <права> <file> - изменить права доступа (r=4, w=2, x=1)
    • chown <user>:<group> <file> - изменить владельца файла
    $ chmod 755 script.sh    # владелец: rwx, группа: r-x, остальные: r-x
$ chmod +x script.sh     # добавить право на выполнение
$ chmod -R 777 dir/      # рекурсивно всем полный доступ (осторожно!)
$ chown appuser:appuser app.py

    Расчёт прав: r=4, w=2, x=1, сумма даёт число (rwx=7, r-x=5, rw-=6). Типичная безопасная настройка: 644 для файлов, 755 для каталогов/скриптов.

    sudo — права администратора

    • sudo <cmd> - выполнить команду с правами root
    • sudo -i - войти в root-сессию
    • sudo -u <user> <cmd> - выполнить от имени другого пользователя
    $ sudo systemctl restart nginx
$ sudo -i   # стать root

    С правами root будь осторожен — любая ошибка может сломать систему.

    Пользователи (кратко)

    • whoami - текущий пользователь
    • id - UID/GID и группы текущего пользователя
    • useradd <name> / userdel <name> - создать/удалить пользователя
    • passwd <user> - сменить пароль
    • usermod -aG <group> <user> - добавить пользователя в группу

    Сеть

    ping — проверка соединения

    • ping <host> - проверка доступности хоста и качества связи
    • ping -c <N> - ограничить число запросов
    $ ping -c 4 ya.ru

    curl / wget — запросы и скачивание

    • curl <url> - отправить HTTP-запрос (по умолчанию GET)
    • curl -X POST -d '{"a":1}' -H "Content-Type: application/json" <url> - POST с телом
    • curl -I <url> - только заголовки ответа (HEAD)
    • curl -o file <url> - сохранить ответ в файл
    • wget <url> - простое скачивание файла
    $ curl -X POST http://localhost:8001/api/orders \
    -H "Content-Type: application/json" \
    -d '{"deliveryAddress":{"galaxy":"Milky Way"}}'

    Postman умеет показывать любой запрос как cURL — удобно для повторения в терминале.

    ip / ss — сети

    • ip addr - сетевые интерфейсы и их адреса
    • ip route - таблица маршрутизации
    • ss -lnt - слушающие TCP-порты
    • ss -tulpn - tcp+udp, слушающие и установленные
    $ ip addr
$ ip route
$ ss -lntp

    ss — современная замена netstat. Флаги: -l (listening), -n (без DNS), -t (TCP), -p (процесс).

    ssh / scp / rsync

    • ssh user@host - подключиться по SSH
    • ssh -i key.pem user@host - подключиться с ключом
    • scp file user@host:/path - скопировать файл по SSH
    • scp -r dir user@host:/path - скопировать каталог по SSH
    • rsync -avz src/ user@host:/dst/ - синхронизация каталогов (быстрая, инкрементальная)

    jq — работа с JSON

    jq — утилита для парсинга и трансформации JSON (обязательна в DevOps/Docker).

    Пример Что делает
    curl -s <url> | jq . красиво распечатать JSON
    curl -s <url> | jq '.items[].name' вытащить все имена из массива
    echo '{"a":1}' | jq '.a' достать значение ключа
    ... | jq 'length' длина массива/объекта
    ... | jq '.status == "UP"' булева проверка/фильтр 
    $ curl -s http://localhost:8000/actuator/health | jq '.status'
$ docker inspect cont --format '{{json .State.Health}}' | jq
$ curl -s $URL | jq '.[] | select(.status=="failed")'

    Диски и архивы

    df / du — место на диске

    • df -h - использование дискового пространства на разделах (human-readable)
    • du -sh <dir> - размер каталога
    • du -sh * - размеры всех элементов текущего каталога
    $ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        40G   12G   26G  32% /

$ du -sh /var/log
510M  /var/log

    df -h показывает, где заканчивается место. du -sh * — что именно его съедает.

    Блочные устройства и монтирование

    • lsblk - схема дисков и разделов
    • blkid - UUID файловых систем
    • df -h - свободное место на смонтированных разделах
    • mount <device> <mountpoint> - смонтировать раздел
    • umount <mountpoint> - размонтировать
    $ lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0   40G  0 disk
└─sda1   8:1    0   40G  0 part /

    lsblk — как посмотреть «структуру диска» без прав root. mount обычно требует sudo.

    tar — архивация

    • tar -czf archive.tar.gz <dir> - создать сжатый архив (.tar.gz = tar + gzip)
    • tar -xzf archive.tar.gz - распаковать
    • tar -tzf archive.tar.gz - просмотреть содержимое
    • tar -xzf archive.tar.gz -C /dst - распаковать в указанный каталог
    $ tar -czf backup.tar.gz /app
$ tar -xzf backup.tar.gz -C /restore

    Ключи: -c (create), -x (extract), -z (gzip), -f (файл), -C (каталог назначения).

    Сервисы (systemd)

    systemctl

    • systemctl <действие> <сервис> - управление сервисами systemd
    Команда Описание Пример
    start Запустить сервис systemctl start nginx
    stop Остановить systemctl stop nginx
    restart Перезапустить systemctl restart nginx
    reload Перечитать конфиг без остановки systemctl reload nginx
    enable Автозапуск при старте системы systemctl enable nginx
    enable --now Автозапуск + сразу запустить systemctl enable --now nginx
    status Статус сервиса systemctl status nginx
    is-active Проверить, активен ли systemctl is-active nginx 
    $ systemctl list-units --type=service   # все сервисы
$ journalctl -u nginx -f                # логи сервиса в реальном времени

    journalctl — логи systemd

    • journalctl -u <service> - логи конкретного сервиса
    • journalctl -f - следить за логами
    • journalctl --since "1 hour ago" - логи за последний час
    • journalctl -p err - только ошибки

    Планировщик cron

    crontab

    • crontab -e - редактировать расписание текущего пользователя
    • crontab -l - показать расписание
    • crontab -r - удалить расписание

    Формат строки cron — 5 полей: 

    ┌───────── минуты (0-59)
│ ┌─────── часы (0-23)
│ │ ┌───── день месяца (1-31)
│ │ │ ┌─── месяц (1-12)
│ │ │ │ ┌─ день недели (0-7, где 0 и 7 = воскресенье)
│ │ │ │ │
* * * * *  команда


    # каждый день в 03:00 — бэкап
0 3 * * *  /opt/backup.sh
# каждую минуту — проверка
* * * * *  curl -f http://localhost/health
# каждый понедельник в 09:30
30 9 * * 1  /usr/local/bin/report.sh

    Troubleshooting (поиск и устранение неисправностей)

    Troubleshooting — систематический процесс выявления, диагностики и решения проблем в ОС.

    Типичный порядок диагностики: 1. Определи, что не работает (сервис, сеть, диск?). 2. Посмотри статус и логи: systemctl status <svc>, journalctl -u <svc> -f. 3. Проверь порты: ss -lntp. 4. Проверь доступность: ping, curl -v. 5. Проверь место на диске: df -h, du -sh *. 6. Проверь процессы: ps aux | grep <name>, top.

    $ systemctl status nginx
$ journalctl -u nginx -f
$ ss -lntp | grep 80
$ curl -v http://localhost/
$ df -h
