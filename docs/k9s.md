# k9s — быстрая навигация по кластеру

**k9s** — терминальный (TUI) обозреватель Kubernetes. Вместо десятков команд `kubectl` вы получаете живой интерактивный список ресурсов: переключаетесь между Pod / Service / Deployment / ConfigMap и т.д. клавишами, а каждый запрос — это `kubectl` под капотом.

> Это не замена `kubectl`, а удобная надстройка для повседневной навигации и диагностики. Команды `kubectl` — на странице [Kubernetes: команды с подробным описанием](k8s-commands.md), теория — [Kubernetes (теория)](k8s.md).

## Установка

```bash
# macOS
brew install k9s

# Linux (бинарник)
curl -sS https://webinstall.dev/k9s | bash

# проверить
k9s version
```

> k9s использует ваш `~/.kube/config` — те же контексты и кластеры, что и `kubectl`. Отдельная настройка не нужна.

## Запуск

```bash
k9s                    # запустить в текущем контексте
k9s -n kube-system     # сразу открыть конкретный namespace
k9s --context <имя>    # сразу открыть конкретный контекст
k9s -A                 # все namespace сразу
```

`k9s` стартует со списком **pods** текущего namespace. Дальше всё — клавишами.

## Основные клавиши навигации

| Клавиша | Действие |
|---|---|
| `1`–`9` | прямое переключение на закладку ресурса |
| `p` | поды (pods) |
| `d` | deployment |
| `s` | service |
| `i` | ingress |
| `c` | configmap |
| `x` | secret |
| `n` | namespace |
| `t` | переключить «все namespace» |
| `Enter` | открыть ресурс (описание / логи пода) |
| `l` | просмотр логов пода |
| `e` | редактировать ресурс (`kubectl edit`) |
| `y` | показать YAML ресурса |
| `d` (внутри под) | описание пода |
| `s` (внутри под) | открыть shell внутри пода |
| `f` | фильтр по тексту (fuzzy) |
| `/` | быстрое переключение по именам ресурсов |
| `?` | полная справка по клавишам |
| `Ctrl+d` / `Ctrl+a` | пролистать историю просмотра |
| `Ctrl+c` | выйти из k9s |

> Не помните клавишу — нажмите `?`, k9s покажет полную таблицу хоткеев прямо в терминале.

## Типовые сценарии в k9s

### Посмотреть и покурить логи упавшего пода
1. `k9s` — открыт список подов
2. стрелками выберите под со статусом `CrashLoopBackOff` или `Error`
3. `Enter` — войти в под, `l` — показать логи
4. `esc` — вернуться к списку

### Зайти в shell контейнера
1. Выберите под, нажмите `Enter`
2. Нажмите `s` — откроется shell внутри контейнера
3. `exit` — выйти обратно

### Поменять число реплик деплоймента
1. `d` — перейти к deployment
2. Выберите деплоймент, нажмите `e` (edit)
3. Измените `spec.replicas`, сохраните

### Через один экран видно машину кластера
k9s показывает статусы и «горячие» ресурсы:
- под со статусом `CrashLoopBackOff` / `Pending` / `ImagePullBackOff` видно мгновенно
- `kubectl get events` доступен прямо из `?`-меню

## Модификаторы команд (`:режим`)

k9s можно запускать определёнными командами через двоеточие:

| Команда | Результат |
|---|---|
| `:pod` | показать список подов |
| `:deploy` | deployment |
| `:svc` | service |
| `:ing` | ingress |
| `:cm` | configmap |
| `:ns` | список namespace |
| `:ctx` | список контекстов |

```bash
k9s :deploy -A    # открыть деплойменты во всех namespace
```

## Почему k9s полезен на практике

- **Быстро** — не надо помнить 20 команд, всё под клавишами
- **Наглядно** — статусы, рестарты и «горящие» поды видны сразу
- **Безопасно** — это read-first инструмент: редактирование/удаление только по явным клавишам
- **Один экран вместо сессии команд** — идеально для диагностики на проде

> Совет: для рутинного разбора деплоя (кто упал, почему, какие логи) k9s экономит кучу времени. Серьёзные изменения всё равно делайте через `kubectl apply -f` из манифестов — это и есть правильный декларативный путь.
