# Bash scripts

> Команды или группу команд можно сохранять в текстовый файл, а после запускать. 


## Примеры скриптов и их описание

Ниже будут приведены примеры скриптов


### Создание скрипта 

1. Создать текстовый файл через `vim <file>.sh` или командый `touch + nano`
2. Записать скрипт в файл
3. Сохранить
4. Выполнить `chmod +x <file>` 
5. Выполнить скрипт `bash <file>` или `./<file>`


### alias

* Псевдонимы или алиасы (англ. alias) — это команды, которые можно определить самостоятельно.

```
ubuntu@linux:~$ alias ll='ls -l'
ubuntu@linux:~$ ll
total 4
-rw-rw-r-- 1 ubuntu ubuntu  0 May 13 17:51 echo
-rwxrwxr-x 1 ubuntu ubuntu 66 May 13 17:31 hello.sh
```


### PATH

* `PATH` - файл, который хранит переменные окружения. Пути к исполняемым файла в директориях

`echo $PATH` - просмотр файла
`export PATH="${PATH}:<новая директория которую хотите добавить>"` - добавление нового пути 

!!!Очень важно
    Переиспользуйте все заданные стандартно директории. Без этого Bash не сможет функционировать привычным для вас образом, так как потеряет доступ к внешним командам.

### Hash

> Чтобы каждый раз не смотреть в PATH, оболочка сперва использует внутреннюю хеш-таблицу для запоминания полного пути к командам, которые уже были запущены.

```
ubuntu@linux:~$ hash
hits	command # hits - указывает на колличество запусков этой команды
   1	/usr/bin/chmod
   1	/usr/bin/man
   3	/usr/bin/ls
   4	/usr/bin/bash
   1	/usr/bin/ps
   4	/usr/bin/vim
```

* Если вы хотите очистить хеш-таблицу, можете использовать команду hash -r.
* Добавление в хеш-таблицу: hash <имя_команды>.
* Удаление из хеш-таблицы: hash -d <имя_команды>.

### Массивы в Bash

В Bash массивы можно объявлять с помощью ключевого слова `declare`

```
$ declare -a MY_ARRAY
$ MY_ARRAY[0]="Hello"
$ MY_ARRAY[1]="World"
$ echo ${MY_ARRAY[0]} ${MY_ARRAY[1]}!
Hello World!
```
Или передавать значения в скобках
```
$ MY_ARRAY=("Hello" "World")
$ echo ${MY_ARRAY[0]}, ${MY_ARRAY[1]}!
Hello, World!
```

> Конструкцию declare -r можно заменить на одно ключевое слово readonly. Атрибут readonly хорошо подходит для больших, развесистых скриптов, где много переменных и сложно отследить, где и какая меняется. 
```
$ readonly MY_VARIABLE="Hello, World!"
$ MY_VARIABLE="Hello, World?"
bash: MY_VARIABLE: readonly variable
```

### Специальные Переменные 

> Bash хранит код возврата последней выполненной команды в специальной переменной `$?`

```
$ bash -c "exit 2"
$ echo $?
2
```

> Переменная `$IFS` (Internal Field Separator) используется для определения символа, который разделяет слова в строках. В операторе циклов `for` список элементов разделяется с использованием значения IFS

```
#!/bin/bash

# Пусть на вход поступает набор слов, разделённых двоеточием
line="home-directory:bash-directory"
# Переопределим IFS
IFS=":"
# Создадим массив
tokens=($line)

echo "${tokens[0]}"  # Выводит "home-directory"
echo "${tokens[1]}"  # Выводит "bash-directory"
```

> Переменная `$$` содержит идентификатор процесса оболочки

> Переменная `$!` содержит идентификатор последнего запущенного фонового процесса


### Оператор | (пайплайн / конвейер)

* `|` - перенаправляет стандартный вывод (stdout) **левой** команды на стандартный ввод (stdin) **правой** команды. Результат левой становится входом правой.

```
$ ls -l | grep "txt"
-rw-r--r-- 1 user user 123 file1.txt
```

```
$ cat app.log | grep -i error | sort | uniq -c   # цепочка команд
```

```
$ docker ps | grep image-compress        # найти контейнер
$ history | grep docker                  # найти команду в истории
```

> Пайплайн можно объединять в цепочку сколько угодно: `команда1 | команда2 | команда3`. Каждая следующая получает вывод предыдущей. Стандартная ошибка (stderr) при этом НЕ передаётся — только stdout. Для ошибок используют `2>&1 |`.

> В `set -o pipefail` код возврата пайплайна = код последней упавшей команды (иначе - код последней команды). Это помогает ловить ошибки в середине цепочки.

### Оператор || (логическое ИЛИ)

* `||` - выполняет **правую** команду, **только если левая завершилась с ошибкой** (ненулевой код возврата). Аналог «иначе»/fallback.

```
$ command1 || command2
# command2 выполнится, только если command1 вернул ошибку (код != 0)
```

```
$ mkdir /existing_dir || echo "Каталог уже существует"
```

```
$ cd /tmp/nonexist || { echo "Нет такого каталога"; exit 1; }
```

```
# типичный паттерн: попытка + логирование ошибки
$ systemctl restart nginx || echo "Не удалось перезапустить nginx"
```

> Ключевое отличие от `|`: `||` — это про **успех/ошибку** (код возврата), а `|` — про **передачу данных**.

### Оператор && (логическое И)

* `&&` - выполняет **правую** команду, **только если левая завершилась успешно** (код 0). Аналог «и», «затем».

```
$ command1 && command2
# command2 выполнится только если command1 завершилась успешно
```

```
$ cd /app && ./start.sh          # зайти в каталог и запустить
$ mkdir dir && cd dir            # создать каталог и войти в него
$ ./build && ./test && ./deploy  # цепочка: только если всё прошло
```

> `&&` и `||` можно комбинировать: `./start && echo OK || echo FAIL` — это удобный короткий паттерн «успех/провал». `&&` удобно использовать в Dockerfile/RUN, чтобы прервать сборку при ошибке шага.

### Сводка: | , || , &&

| Оператор | Что делает | Условие выполнения правой части |
|----------|------------|---------------------------------|
| `\|` | Передаёт stdout левой на stdin правой | всегда (данные) |
| `\|\|` | Выполняет правую, если левая ОШИБКА | левая вернула ненулевой код |
| `&&` | Выполняет правую, если левая УСПЕШНА | левая вернула код 0 |

```
$ ls | grep md            # передаём данные
$ cd /tmp/x || exit       # если нет каталога — выходим
$ ./build && ./test       # запуск только после успеха
```

### Ввод аргумента и if-else 

```
if [ "$1" ] ; then
        echo "Hello {$1}"
else
        echo "Hello World"
fi
```

Описание: 

* `if` объявление начала консрукции
* В квадратных скобках пишется условие. В данном случае мы ожидаем "что-то" в первом аргументе, который передадим скрипту
* После скобок идет `; then`, что выполниться в случае выполнения условия
* * Скрип выведет в терминал `Hello <переданный аргумент>`
* `else` чтобы будет, если условие не выполнено.
* * В терминале будет `Hello World`
* `fi` закрытие конструкции

!!! Подсказка
    Аргументы в скриптах Bash доступны через переменные $1, $2, $3 и т.д.

### Цикл for

* `for` - перебор элементов (по списку, по диапазону, по файлам)

```
#!/bin/bash
# по списку
for name in Оля Дима Лена; do
    echo "Привет, $name"
done

# по диапазону чисел
for i in $(seq 1 5); do
    echo "Итерация $i"
done

# по файлам в каталоге
for file in *.txt; do
    echo "Нашли файл: $file"
done
```

### Цикл while

* `while` - повтор, пока выполняется условие

```
#!/bin/bash
count=1
while [ $count -le 5 ]; do
    echo "Счёт: $count"
    count=$((count + 1))
done

# Бесконечный цикл с выходом (полезен для мониторинга)
while true; do
    uptime
    sleep 5
done
```

### Операторы сравнения

В `[ ]` сравнение делается не через `==`/`>`, а через специальные операторы:

| Оператор | Описание | Пример |
|----------|----------|--------|
| `-eq` | равно (числа) | `[ $a -eq 5 ]` |
| `-ne` | не равно | `[ $a -ne 5 ]` |
| `-gt` | больше | `[ $a -gt 5 ]` |
| `-lt` | меньше | `[ $a -lt 5 ]` |
| `-ge` | больше или равно | `[ $a -ge 5 ]` |
| `-le` | меньше или равно | `[ $a -le 5 ]` |
| `=` | равно (строки) | `[ "$name" = "admin" ]` |
| `!=` | не равно (строки) | `[ "$name" != "admin" ]` |
| `-d` | существует каталог | `[ -d /etc ]` |
| `-f` | существует файл | `[ -f /etc/hosts ]` |
| `!` | отрицание | `[ ! -d /tmp ]` |
| `-z` | строка пустая | `[ -z "$var" ]` |

```
if [ "$1" = "admin" ]; then
    echo "Доступ разрешён"
elif [ -f /etc/hosts ]; then
    echo "Файл существует"
else
    echo "Доступ запрещён"
fi
```
> Расширенные версии: `[[ ... ]]` (для строк и регулярок) и `((...))` (для арифметики): `(( a > 5 ))`.

### case

* `case` - выбор по нескольким вариантам (аналог switch)

```
#!/bin/bash
case "$1" in
  start)
    echo "Запуск..."
    ;;
  stop)
    echo "Остановка..."
    ;;
  restart)
    echo "Перезапуск..."
    ;;
  *)
    echo "Неизвестная команда"
    ;;
esac
```

### Функции

* `имя() { ... }` - объявление функции, вызывается по имени

```
#!/bin/bash

greet() {
    echo "Привет, $1"   # $1 — первый аргумент функции
}

greet "Мир"

# Функция с возвратом значения
is_even() {
    if (( $1 % 2 == 0 )); then
        return 0    # 0 = true (успех)
    else
        return 1    # 1 = false (ошибка)
    fi
}

if is_even 4; then
    echo "4 — чётное"
fi
```
> Переменные `$1`, `$2` внутри функции — это её аргументы, а не аргументы скрипта. Код возврата функции — через `return`.

### Полный пример резервного копирования

Соберём всё вместе — скрипт, который бэкапит каталог с проверками:

```
#!/bin/bash
set -euo pipefail    # строгий режим: выход при ошибке, неопределённых переменных

BACKUP_DIR="/backups"
SOURCE="/app/data"
DATE=$(date +%Y%m%d_%H%M%S)

# проверяем, что исходный каталог существует
if [ ! -d "$SOURCE" ]; then
    echo "Ошибка: каталог $SOURCE не найден"
    exit 1
fi

# создаём каталог для бэкапов
mkdir -p "$BACKUP_DIR"

# создаём архив
tar -czf "$BACKUP_DIR/data_$DATE.tar.gz" -C "$SOURCE" .

echo "Бэкап создан: $BACKUP_DIR/data_$DATE.tar.gz"
```


> `set -euo pipefail` — важная строка в начале серьёзных скриптов: `-e` (остановиться при ошибке), `-u` (ошибка при неопределённой переменной), `-o pipefail` (ошибка, если упала любая команда в пайпе).

### set - флаги режима скрипта

| Флаг | Что делает |
|------|------------|
| `set -e` | Остановка скрипта при ошибке любой команды |
| `set -u` | Ошибка при обращении к неопределённой переменной |
| `set -x` | Трассировка: выводить каждую выполняемую команду |
| `set -o pipefail` | Ошибка пайпа, если упала любая его часть |
| `set +e` | Отключить `-e` |

> Рекомендуемый старт скрипта: `#!/bin/bash set -euo pipefail` — отлавливает почти все типичные ошибки.
