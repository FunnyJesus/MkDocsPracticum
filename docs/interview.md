# Вопросы к собеседованию DevOps

Частые вопросы с короткими ответами и ссылками на подробные разделы конспекта. Для ежедневного повторения — [Мантра: вопросы на каждый день](interview-mantra.md). Короткий ответ — чтобы сформулировать мысль; ссылка — чтобы уметь ответить на уточняющие вопросы.

!!! tip "Как отвечать"
    Структура: **определение → зачем → пример из практики**. «Не знаю, но рассуждал бы так…» лучше, чем уверенная выдумка. Для практических задач — проговаривай вслух порядок диагностики.

## Общее

??? question "Что такое DevOps?"
    Культура и практики, которые объединяют разработку и эксплуатацию, чтобы выпускать изменения часто, быстро и надёжно: автоматизация (CI/CD, IaC), маленькие изменения, измерения, общая ответственность. → [DevOps](devops.md)

??? question "Что такое метрики DORA?"
    Deployment Frequency, Lead Time for Changes, Change Failure Rate, Time to Restore. Первые две — скорость, вторые — стабильность. → [DevOps](devops.md)

??? question "Чем Continuous Delivery отличается от Continuous Deployment?"
    Delivery — каждое изменение **готово** к выкатке в прод, но выкатка по кнопке. Deployment — выкатывается в прод **автоматически** без участия человека. → [CD](cd.md)

## Linux

??? question "Что такое load average и как его интерпретировать?"
    Среднее число процессов, которые выполняются или ждут CPU/диск, за 1, 5 и 15 минут. Сравнивают с числом ядер: load 8 на 8 ядрах — полная загрузка, на 2 ядрах — перегрузка. Высокий load при низком CPU — ждут диск. → [Linux: диагностика](linux-troubleshooting.md)

??? question "Сервер тормозит. Твои действия?"
    `uptime` (load), `dmesg -T | tail` (OOM, ошибки диска), `free -h`, `df -h` и `df -i`, `top` (кто ест CPU/память, `wa`), `iostat -xz`, `ss -s`, логи сервиса. Плюс вопрос «что менялось». → [Linux: диагностика](linux-troubleshooting.md)

??? question "Место на диске есть, а писать нельзя. Почему?"
    Кончились inodes (`df -i`) или файловая система смонтирована read-only после ошибки. Обратная ситуация — удалили файл, а место не освободилось — процесс держит файл открытым (`lsof +L1`).

??? question "Чем отличаются SIGTERM и SIGKILL?"
    SIGTERM (15) — просьба завершиться, процесс может корректно закрыть соединения. SIGKILL (9) — немедленное убийство ядром, перехватить нельзя. Kubernetes при остановке пода шлёт SIGTERM, ждёт `terminationGracePeriodSeconds` (30 с), затем SIGKILL.

??? question "Что такое процесс-зомби?"
    Процесс завершился, но родитель не прочитал его код выхода (`wait`). Ресурсов почти не занимает, кроме записи в таблице процессов. Лечится исправлением/перезапуском родителя.

??? question "Как найти, кто занял порт 8080?"
    `ss -tulpn | grep 8080` или `lsof -i :8080`.

## Сети

??? question "Что происходит, когда вводишь адрес в браузере?"
    DNS-резолв имени → TCP-соединение (3-way handshake) → TLS-handshake (для HTTPS) → HTTP-запрос → обработка (балансировщик → приложение → база) → ответ → рендер. На каждом шаге можно рассказать детали. → [Сети](networking.md)

??? question "TCP vs UDP?"
    TCP — с установкой соединения, гарантией доставки и порядка (HTTP, SSH, базы). UDP — без соединения и гарантий, но быстрее (DNS, видео, VoIP, QUIC/HTTP3). → [Сети](networking.md)

??? question "502 и 504 — в чём разница?"
    502 Bad Gateway — прокси получил от бэкенда отказ или некорректный ответ (бэкенд лежит, не тот порт). 504 Gateway Timeout — бэкенд не ответил за отведённое время. → [Nginx](nginx.md)

??? question "Reverse proxy vs forward proxy?"
    Forward — перед клиентами, ходит в интернет от их имени. Reverse — перед серверами, принимает запросы клиентов и распределяет по бэкендам (Nginx, Ingress). → [Nginx](nginx.md)

## Git

??? question "merge vs rebase?"
    Merge сохраняет историю как есть и создаёт merge-коммит. Rebase переписывает коммиты ветки поверх целевой — история линейная. Правило: не делать rebase уже опубликованных общих веток. → [Git](git.md)

??? question "Секрет попал в git. Что делать?"
    1) **Сразу отозвать/сменить секрет** — он скомпрометирован. 2) Удалить из истории (`git filter-repo`/BFG) и force push, если репозиторий публичный. 3) Добавить gitleaks в pre-commit/CI. → [Безопасность](security.md)

## Docker

??? question "Чем контейнер отличается от виртуальной машины?"
    VM виртуализирует железо и имеет своё ядро ОС. Контейнер — изолированный процесс на **общем ядре** хоста (namespaces + cgroups): легче, стартует за секунды, но изоляция слабее. → [Docker](docker.md)

??? question "CMD vs ENTRYPOINT?"
    ENTRYPOINT — что запускается всегда; CMD — аргументы по умолчанию (переопределяются в `docker run image <args>`). Часто: `ENTRYPOINT ["python", "app.py"]` + `CMD ["--port", "8000"]`.

??? question "Как уменьшить размер образа?"
    Multi-stage сборка, slim/distroless/alpine база, `.dockerignore`, объединение `RUN` и очистка кеша пакетного менеджера в том же слое, порядок слоёв (редко меняющееся — выше). → [Docker](docker.md)

??? question "Почему не стоит использовать тег latest в проде?"
    Он изменяемый: неизвестно, что именно запущено, откат на «тот же» тег может поднять другой образ. Использовать SHA коммита / версию / digest. → [Registry](registry.md)

## Kubernetes

??? question "Из каких компонентов состоит кластер?"
    Control plane: kube-apiserver, etcd, kube-scheduler, kube-controller-manager. На нодах: kubelet, kube-proxy, container runtime (containerd). → [K8s](k8s.md)

??? question "Deployment vs StatefulSet vs DaemonSet?"
    Deployment — взаимозаменяемые stateless-поды. StatefulSet — стабильные имена, порядок запуска и свой том у каждого пода (базы, Kafka). DaemonSet — по поду на каждой ноде (агенты логов и мониторинга). → [K8s](k8s.md)

??? question "Liveness vs readiness vs startup probe?"
    Readiness — готов ли принимать трафик (нет → убрать из Service). Liveness — жив ли (нет → перезапустить контейнер). Startup — для медленного старта: пока не пройдёт, liveness не проверяется. Частая ошибка — liveness проверяет базу, и при её падении все поды перезапускаются по кругу.

??? question "requests vs limits?"
    Requests — гарантированный минимум, по нему scheduler выбирает ноду. Limits — потолок: превышение памяти → OOMKilled, CPU → throttling.

??? question "Типы Service?"
    ClusterIP (внутри кластера), NodePort (порт на каждой ноде), LoadBalancer (внешний балансировщик облака), ExternalName (DNS-алиас). → [K8s LoadBalancer](k8s-loadbalancer.md)

??? question "Ingress vs Gateway API?"
    Оба описывают входящий HTTP-трафик. Ingress заморожен, расширенные функции — через аннотации конкретного контроллера. Gateway API — новый стандарт: роли (GatewayClass/Gateway/HTTPRoute), canary, заголовки, TCP/gRPC в спецификации, переносимость между реализациями. → [Gateway API](gateway-api.md)

??? question "Под в CrashLoopBackOff. Что делаешь?"
    `kubectl describe pod` (Events, Last State, Exit Code), `kubectl logs --previous`. Дальше по причине: ошибка приложения/конфига, OOMKilled (137), неудачная liveness probe, неверная команда. → [Типовые инциденты](incidents-practice.md)

??? question "Как сделать деплой без простоя?"
    RollingUpdate (`maxUnavailable: 0`), readiness probe, 2+ реплики, PodDisruptionBudget, graceful shutdown (обработка SIGTERM, `preStop`), обратно совместимые миграции. → [CD: стратегии](cd-strategies.md)

??? question "Helm vs Kustomize?"
    Helm — шаблоны + values, упаковка чартов, релизы и откаты. Kustomize — патчи поверх обычного YAML без шаблонов, встроен в kubectl. Часто вместе: чужой софт — Helm, свои сервисы — Kustomize. → [Kustomize](kustomize.md), [Helm](helm.md)

## CI/CD и GitOps

??? question "Из каких этапов состоит типичный пайплайн?"
    Lint → unit-тесты → сборка образа → сканирование → push в registry → деплой в dev/staging → интеграционные/smoke-тесты → деплой в прод (часто вручную или через MR). → [CI](ci.md)

??? question "Стратегии деплоя?"
    Recreate, Rolling update, Blue-Green (два окружения, переключение трафика), Canary (небольшой процент трафика на новую версию), A/B, feature flags. → [CD: стратегии](cd-strategies.md)

??? question "Что такое GitOps? Push vs pull?"
    Git — единственный источник правды; агент в кластере (Argo CD, Flux) сам тянет изменения и исправляет drift. Push — CI сам применяет изменения в кластер и держит от него доступы. → [GitOps](gitops.md)

## IaC

??? question "Terraform vs Ansible?"
    Terraform — декларативно **создаёт инфраструктуру** (сети, VM, кластеры, DNS), хранит state. Ansible — **настраивает** существующие серверы (пакеты, конфиги, сервисы), без state, по SSH. Часто вместе. → [IaC](iac.md), [Ansible](ansible.md)

??? question "Что такое state в Terraform и где его хранить?"
    Соответствие кода и реальных ресурсов. Хранить в remote backend (S3/GCS/GitLab) с блокировкой и версионированием; содержит секреты — ограничивать доступ; не коммитить. → [Terraform продвинутый](terraform-advanced.md)

??? question "count vs for_each?"
    `for_each` даёт ресурсам стабильные ключи; с `count` удаление элемента из середины сдвигает индексы и пересоздаёт соседние ресурсы. → [Terraform продвинутый](terraform-advanced.md)

??? question "Что такое идемпотентность?"
    Повторное применение даёт тот же результат, без лишних изменений. Ключевое свойство Ansible-задач, Terraform, миграций и обработчиков сообщений.

## Мониторинг и SRE

??? question "Метрики, логи, трейсы — зачем каждое?"
    Метрики — что и сколько (агрегаты, алерты). Логи — детали конкретного события. Трейсы — где в цепочке сервисов теряется время. → [Мониторинг](monitoring.md), [Трейсинг](tracing.md)

??? question "SLI, SLO, SLA, error budget?"
    SLI — метрика качества; SLO — внутренняя цель; SLA — обещание клиенту с санкциями; error budget = 100% − SLO, «право на ошибку», которое тратится на релизы и риски. → [SRE](sre.md)

??? question "Методики RED и USE?"
    RED (для сервисов): Rate, Errors, Duration. USE (для ресурсов): Utilization, Saturation, Errors. → [Мониторинг](monitoring.md)

??? question "Что такое blameless postmortem?"
    Разбор инцидента без поиска виноватых: хронология, причины, что сработало, action items с ответственными и сроками. Цель — исправить систему. → [SRE](sre.md)

??? question "RPO и RTO?"
    RPO — сколько данных допустимо потерять (частота бэкапов). RTO — сколько допустимо не работать (скорость восстановления). → [Бэкапы и DR](backup-dr.md)

## Безопасность

??? question "Kubernetes Secret — это безопасно?"
    По умолчанию — только base64, не шифрование. Нужны encryption at rest в etcd, RBAC на чтение секретов и внешний менеджер секретов (Vault + ESO, облачный Secret Manager). → [Секреты](secrets.md)

??? question "Как хранить секреты в GitOps?"
    В git — только зашифрованное или ссылки: SOPS, Sealed Secrets, External Secrets Operator. → [Секреты](secrets.md)

??? question "Что такое принцип наименьших привилегий?"
    Давать ровно те права, которые нужны: non-root в контейнере, отдельные ServiceAccount и RBAC, IAM-роли CI с минимальным доступом, пользователи БД без суперправ. → [Безопасность](security.md)

## Базы данных и очереди

??? question "Репликация — это бэкап?"
    Нет. Реплика повторит и ошибочный `DROP TABLE`. Репликация защищает от падения сервера, бэкап — от потери/порчи данных. → [Бэкапы и DR](backup-dr.md)

??? question "Приложение пишет too many connections. Что делать?"
    Посмотреть `pg_stat_activity`, закрыть зависшие соединения, уменьшить пул на экземпляр, поставить PgBouncer, посчитать `экземпляры × пул < max_connections`. → [Базы данных](databases.md)

??? question "Kafka vs RabbitMQ?"
    RabbitMQ — очередь задач с гибкой маршрутизацией, сообщение удаляется после подтверждения. Kafka — распределённый журнал событий с хранением и перечитыванием, высокая пропускная способность, порядок внутри партиции. → [Очереди сообщений](message-queues.md)
