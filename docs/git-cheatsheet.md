# Git: шпаргалка топ-20 команд

Самое частое в ежедневной работе с Git. Минимум слов — быстрый доступ.

> Подробно по каждой команде: [Git: команды с подробным описанием](git-commands.md). Теория — [Git (теория)](git.md).

## Топ-20 команд

| # | Задача | Команда | Что делает |
|---|---|---|---|
| 1 | настройка | `git config --global user.name "Name"` | задать имя автора |
| 2 | настройка | `git config --global user.email "e@x.ru"` | задать email автора |
| 3 | старт | `git init` | создать репозиторий |
| 4 | старт | `git clone <url>` | скопировать удалённый репозиторий |
| 5 | статус | `git status` | состояние рабочего каталога и индекса |
| 6 | статус | `git diff` | изменения незакоммиченных файлов |
| 7 | история | `git log --oneline --graph` | история коммитов (кратко, с графом) |
| 8 | история | `git show <hash>` | что изменил конкретный коммит |
| 9 | индекс | `git add .` | добавить все изменения в индекс |
| 10 | коммит | `git commit -m "msg"` | создать коммит |
| 11 | коммит | `git commit -am "msg"` | `add` всех + коммит одной командой |
| 12 | ветки | `git branch` | список веток |
| 13 | ветки | `git branch <name>` | создать ветку |
| 14 | ветки | `git checkout -b <name>` | создать ветку и переключиться |
| 15 | ветки | `git checkout <branch>` | переключиться на ветку |
| 16 | слияние | `git merge <branch>` | влить ветку в текущую |
| 17 | remote | `git push` | отправить коммиты на удалённый репозиторий |
| 18 | remote | `git pull` | скачать и слить обновления (`fetch`+`merge`) |
| 19 | откат | `git reset --hard HEAD` | откатить файлы к последнему коммиту ⚠️ |
| 20 | поиск | `git blame <file>` | кто и когда менял строки файла |

## Компактный everyday-сценарий

```bash
git status                  # что изменилось?
git diff                    # посмотреть изменения
git add .                   # застейджить всё
git commit -m "fix: typo"   # зафиксировать
git push                    # отправить в remote
```

## Работа с ветками (feature → merge)

```bash
git checkout -b feature/xyz   # ветка + переключение
# ... правки ...
git add . && git commit -m "feat: xyz"
git push origin feature/xyz   # пуш НОВОЙ ветки (origin + имя!)

# вернуться и влить
git checkout main
git merge feature/xyz
git push
```

## Откат изменений

```bash
git checkout HEAD~1 <file>   # вернуть файл к предыдущему состоянию
git reset --hard HEAD        # жёсткий откат к последнему коммиту ⚠️ стирает правки
git revert <hash>            # безопасный откат через НОВЫЙ коммит (рекомендуется)
```

> ⚠️ `git reset --hard` необратим — использовать осторожно. Из практики лучше `git revert` (новый коммит), чем переписывать историю.

## Мини-памятка по синтаксису

- `git pull` = `git fetch` + `git merge`
- `git commit -am` = `git add` (все) + `git commit -m`
- `git checkout -b` = `git branch` + `git checkout`
